Worktree: `d:\Research\Brain_Registration_Projects\brain-group-rad\.worktrees\ablation-prereqs` (branch `ablation-prereqs` off main 8e12596). All paths below are relative to the worktree. Linear-heads finding and the group-config mapping: `linear-heads.md` (same folder).

## Decisions

- D1 Option names. `ModelConfig.group_config` stays a string; `GROUP_CONFIGS = ("A", "B", "none", "E")`. A = group blocks everywhere, B = both decoders only (final), E = stem/encoder only, none = no group blocks. A/B keep their names, so every existing config.json loads unchanged. Two methods on ModelConfig (methods, not dataclass fields, so `to_dict` and config.json do not change): `group_encoder()` = config in (A, E); `group_decoders()` = config in (A, B). Every `group_config == "A"` test and every hard-coded `group=True` of the linear-decoder reductions, `dense_1` and the deform decoder stages switches to these methods. For A and B the booleans equal today's, so the built graphs and the goldens are bit-identical.
- D2 Linear heads (Jay via orchestrator, option 2): `none` removes every group concat in the network; E has a grouped encoder and ungrouped linear and deform decoders. `--dense-group-concat-first true` with `none` / E -> ValueError in `ModelConfig.validate` (the argparse error comes from it via `model_config_from_args`). BN in train mode still couples the group; documented, not changed.
- D3 Mixed group configs across cascade levels: REJECTED. This needs no new code: `runtime/checkpoint.check_cascade_config` and `FrozenChain.__init__` already require identical ModelConfigs (seed excepted), and `group_config` and `norm` are ModelConfig fields. A new test pins this behaviour for the new values. Reason: frozen stages run in front of the trainable one with the same ModelConfig in every cascade code path. Allowing a mix would mean a per-stage config in config.json, FrozenStage, FrozenChain and the predict loader, and the ablation does not need it.
- D4 Instance norm under AMP: `InstanceNormWithAffine` already computes the moments and the normalisation in float32 and casts back (layers.py 497-515), so the fp16 numerics are safe. No dtype change. Its float32 temporaries at full resolution are not in the memory model (which ignores norm type). The L1 smoke measures them. Fallback if the IN L1 smoke exceeds ~41500 MB: `MIN_PAIRS=1` (a float32 decoder would need more memory, not less); report only. BN recal/freeze: `--bn-recal-batches > 0 --norm instance` already exits in `runtime/args.py` 826. The scripts gain a `NORM` env that forces `BN_RECAL_BATCHES=0` and is the only way the cascade passes `--norm`. `--bn-recal-freeze true` with 0 batches is a no-op (the parser default).
- D5 Streaming exactness: `_apply_block` already branches on `block.group`, and IN has no running statistics (per image), so streaming stays exact. The streaming engine changes only to skip group sums for ungrouped decoder stages (needed for correctness of the stats bookkeeping and to avoid full-resolution wasted work) and the element bound for ungrouped decoder concats.
- D6 From-scratch L1: new `slurm/r_level1_scratch.sh` (separate script; r_level1.sh stays cascade-only). Schedule = the L4 phase-C schedule as fractions of STEPS: WARMUP STEPS/16, DEFORM_START 3*STEPS/16, DEFORM_RAMP STEPS/32, CURRICULUM_RAMP 3*STEPS/16, G_START 3*STEPS/16, G_RAMP 3*STEPS/16 (= 1000/3000/500/3000/3000/3000 at 16000), integer division in bash, each overridable by env. Recipe otherwise = final L1: d12hs, float32_fine, `--group-config B --lambda-smooth 15` via the script defaults GROUP_CONFIG=B / SMOOTH=15 (the cascade scripts take these through EXTRA_ARGS; here they are first-class env vars so the smoke and long lines are short), Dice+LNCC 1/1, ratio 1:1:2, N 8 / DEFORM_N 4, lr 3e-4, AdamW wd 1e-1, TF_MEM_LIMIT_MB 42500, pair recompute, lean losses, val image/pair chunk 1/1, val group size = N (empty), BN trainable, no recal (no cascade source), curriculum on, G 45/10. STEPS is REQUIRED (no default): the cosine schedule and the fractions depend on it and must stay constant over resumes (main.py resumes from ckpt/last with the same RUN_NAME). `#SBATCH --time=48:00:00 --mem=128G`.
- D7 GPU-hours budget (sacct on mlsc, read 2026-11-12): L4 10623341 13:54:14 + L2 10624169 27:20:44 + L1 10627751 22:36:02 = 63.85 h (229 860 s) on RTX 8000. Step-count rule for the report: STEPS = floor(229 860 / (mean_step_s + 462 / VAL_EVERY + small startup)) using the smoke's `INFO step_time` mean step and the measured validation pass (L1 ~462 s per pass). Example: 11 s mean step, VAL_EVERY 500 -> ~19 300 steps. Caveat for the paper: the L2 job shared its node with another job part of the time.
- D8 r_cascade.sh: GROUP_ARGS already exists (default `--group-config B`). New env `NORM` (batch | instance, default batch). instance -> `--norm instance` appended to every level's EXTRA_ARGS and `BN_RECAL_BATCHES=0` in the L2 and L1 env. `group_args` and `norm` are recorded in the chain state file and compared on resume. A state file without the key counts as the old default (`--group-config B` / batch), so chains started before this change resume unchanged.
- D9 Ablation launch = r_cascade.sh with the final recipe: S4=2.5 S2=10 S1=15 SYNTH_PROB=0 STEPS_L2=16000 STEPS_L1=6000 EXTRA_ARGS_L2='--frozen-integration-grid current', plus GROUP_ARGS / NORM per variant. The variants are GROUP_ARGS='--group-config none' | E | A, and NORM=instance with B. Expected ~64 h each (< the 72 h limit; resubmit the identical line if hit).

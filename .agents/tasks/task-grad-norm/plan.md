## Background (measured; carry into the design-doc note)

- One shared Adam (lr 3e-4) on a shared encoder; each step is one task (rigid / affine / deform) drawn by `--task-ratio`. Optimizer built by `runtime/optimizers.py::make_optimizer` with `global_clipnorm` = `--clipnorm` 12; under AMP it is wrapped in a `LossScaleOptimizer` and the trainer reads the clip through `O.inner_optimizer(opt).global_clipnorm`. TF 2.10's experimental optimizer always runs `tf.clip_by_global_norm(grads, clip)` = `grads * (clip * min(1/n, 1/clip))`.
- Linear losses are mm^2: raw total grad norms 1e3-6e3, every linear step clipped to 12. Deform loss (soft Dice + smoothness, optional LNCC): raw total norms ~0.03-0.5, never clipped. Adam's second moment on shared encoder weights mixes tasks, so the unweighted deform task barely moved the encoder (applied encoder grad 0.047-0.05 vs ~3.4 rigid).
- Fix used so far: `--task-loss-weights deform:64` pushed deform total norms to 30-75, so every step of every task was clipped to 12 (de facto per-task normalisation). Val deform template / pair Dice at step 8000: 0.723 / 0.638 (w64, job 10493723) vs 0.704 / 0.608 unweighted (job 10493712); linear unchanged. `slurm/m7_three_task.sh` defaults `TASK_LOSS_WEIGHTS=deform:64` (`none` = unweighted).
- Right after a warm start the SVF head is zero-initialised: deform gradient into the encoder ~1e-10 (3.8e-10 measured, milestone-7 report) while the deform total norm (head kernels) is ~0.03-0.5.
- Existing diagnostics: `train_<task>/diag_enc_grad_norm_raw`, `diag_enc_grad_norm_eff`, `train_<task>/grad_norm` (pre-clip total norm), `train/grad_norm` (pooled).

## Design decisions

1. Semantics (Jay's version). Per task step, after the gradients are computed and AMP-unscaled, before `apply_gradients`: `g = global_norm(grads)`; if `isfinite(g) and g >= min`: `grads *= target * (1.0 / max(g, eps))`; else scale = 1 (gradients left as they are). The global clip stays as is (with target <= clipnorm it is a no-op up to float rounding).
   - `scale = target * (1.0 / tf.maximum(g, eps))` with Python `1.0 /` (RealDiv), deliberately mirroring `tf.clip_by_global_norm`'s `clip_norm * (1.0 / use_norm)`; this makes the clip-equivalence test bit-exact (decision 7).
   - `eps = 1e-12` module constant `TASK_GRAD_NORM_EPS` (same value as the existing `tf.maximum(gnorm, 1e-12)` in `_enc_grad_diagnostics`), not a flag. It only matters when `--task-grad-norm-min 0`.
2. Default minimum `--task-grad-norm-min 1e-3`. Rationale: normal deform totals are 0.03-0.5 (30-500x above), linear totals 1e3+, so in healthy training no step is gated; it equals `collapse_grad_norm` = 1e-3, so exactly the steps that the collapse detector already calls "zero gradient" (group collapse, all-zero / degenerate batches) are not amplified; the maximum gain is target / min = 1.2e4 at target 12. The zero-head deform steps after a warm start have total norm 0.03-0.5 (not gated): they are scaled by ~24-400, which boosts the SVF-head gradient (so the head grows faster) while the encoder part stays ~1e-10 x 400 = 4e-8, i.e. harmless.
   - Discontinuity at the gate: as g crosses min the scale jumps from 1 to target/min (1.2e4); the applied norm jumps from ~1e-3 to 12. Under Adam it matters only if a task hovers near the gate for many steps (its contributions to m / v would flip between tiny and full size); with the gate 30x below the smallest healthy norm this is not expected. Logged as `grad_norm_gated_frac` so it is visible.
   - Alternative noted, NOT implemented: capped gain `scale = min(target / g, max_gain)` (continuous; equals Jay's version above g = target / max_gain except that small norms get max_gain instead of 1).
3. Order with task weights: normalise FIRST, then multiply by the task weight. When the flag is on, the task weight is NOT put into the objective; instead the applied gradient is `grads_raw * scale * w` (gated steps: `grads_raw * w`). Thus `--task-loss-weights` become clean relative ratios of applied norms (target * w). This changes the meaning of the weights only when the flag is on. `--loss-scale-mm2` stays in the linear objective (it cancels under normalisation; it only shifts which raw norm the gate sees, documented). Caveat to document: with the global clip kept at 12 and target 12, weights > 1 are clipped back to 12 (only w < 1 has an effect); use `TASK_LOSS_WEIGHTS=none` with normalisation, or target * max(w) <= clipnorm.
4. Logging. `grad_norm` stays the RAW pre-normalisation total norm (with the flag on this is the norm of the unweighted objective's gradient, since the weight is applied after; with the flag off it is unchanged, i.e. the weighted pre-clip norm). `collapse_grad_norm` keeps reading it. New per-step keys only when the flag is on (like `DEFORM_NCC_KEYS`): `grad_norm_scale` (the normalisation factor, 1 when gated), `grad_norm_gated_frac` (1.0 if gated else 0.0; window mean = gated fraction), `grad_norm_normed` (global norm of the gradients actually passed to `apply_gradients`, before the optimizer's clip), so `grad_norm_normed == grad_norm * grad_norm_scale * w`. Window keys `train_<task>/grad_norm_scale`, `train_<task>/grad_norm_gated_frac`, `train_<task>/grad_norm_normed`. `diag_enc_grad_norm_eff` = encoder norm actually applied: raw encoder norm x scale x w x min(1, clip / (g x scale x w)).
5. Non-finite steps: unchanged handling. The scale is `tf.where(isfinite(g) & (g >= min), target * (1/max(g, eps)), 1.0)`, so NaN / inf gradients are never rescaled (inf x 0 would make NaN; NaN >= min is False anyway). The `finite` flag is computed from the raw norm exactly as now; non-AMP: `tf.cond(finite, apply, skip)`; AMP: the LSO still receives the (unscaled-by-us) non-finite gradients and skips / lowers its scale itself; BN rollback unchanged. Non-finite steps are not accumulated into windows (existing `fit` logic).
6. Off = bit-identical: `cfg.task_grad_norm == 0` -> no new ops, no new result keys, the objective weight multiply and `_enc_grad_diagnostics` ops are exactly as today. Goldens `TestLinearOnlyUnchanged` (`tests/fixtures/m7_linear_golden.json`) and `TestDeformUnchanged` (`tests/fixtures/lncc_deform_golden.json`) must pass with max |diff| 0. Do NOT regenerate fixtures.
7. Equivalence with clipping: with weights w = 2^k (power of two) every forward/backward value is scaled exactly by w, the global norm exactly by w, and `clip * (1.0 / (w g)) * (w x)` equals `target * (1.0 / g) * x` bit for bit. So a run with `--task-grad-norm 12`, no weights and the optimizer clip OFF should match a run with clip 12 and weights 2^14 bit-exactly; with the clip kept at 12 (the real recipe) the extra `clip_by_global_norm` factor `12 * min(1/n', 1/12)` (n' = 12 +- ulp) differs from 1 by ~1 ulp, so only near-equality is expected there.
8. CLI validation: both values must be finite and >= 0 (parser.error in `runtime/args.py`, ValueError in `Trainer.__init__`); `--task-grad-norm 0` = off (min ignored).
9. `tests/gpu/check_mixed_run.py`: when `train_<task>/grad_norm_scale` keys exist, append median scale and mean gated fraction to the existing `enc_grad_<task>` detail string (no new result names, so `test_check_mixed_run` name lists stay valid).

## Gaps / assumptions

- "Leave the raw gradients" for gated steps is implemented as `raw * w` (the weight still applies after the normalisation stage); with `TASK_LOSS_WEIGHTS=none` (recommended) this is exactly the raw gradient.
- With the flag on, logged `grad_norm` is the norm of the unweighted gradient (the weight moved out of the objective); with the flag off it is unchanged. Documented in the args help and design note.
- If the bit-exact A0 vs B equivalence fails (e.g. a GPU kernel not exactly linear under power-of-two scaling), the test falls back to the stated tolerance and the implementer reports the measured difference and cause rather than loosening silently.

# Optional fine-grid integration of frozen cascade stages (training flag + matching predict path)

The branch adds `--frozen-integration-grid native|current` to training and `--integration-grid auto|native|fine` to `predict.py run|check-streaming`. In `current` mode, frozen-stage SVFs are upsampled to the grid of the level being trained, integrated there one image at a time, and composed in cascade order. Inference follows the checkpoint's record by default. The switch lives entirely in `models/cascade.py` (`FrozenStage` / `FrozenChain.integration_grid`), so `runtime/run.py` is untouched. Train steps, skips, validation baselines, BN recalibration and eval_run get the new math through the existing `deform` / `deform_stages` / `deform_skip` calls. Native branches are verbatim, goldens report 0 diff, and no existing script default changed. A new `slurm/fgi_memory.sh` measures L2/L1 native vs current with the real trainer. It was not submitted.

Watch for: only efficiency and record-keeping gaps in the fine inference path: repeated 1 mm integrations per chunk and per TTA flip, the non-lean sampler, check-streaming not recording the grid used, and a host-store estimate that leaves out the SVF stores. None of these affects correctness or the native default.

**Verdict**: APPROVED

## High-level view

The training math matches the request and plan D3. At level 2, `U, U_inv` = exp at 2 mm of up(v4). At level 1, the frozen level-2 model is pre-warped with exp at 2 mm of up(v4), which is what it saw in its own `current` training. Then `U = exp(up²v4) ∘ exp(up v2)` at 1 mm, in `compose_cascade` order. Everything is wrapped in `stop_gradient` and runs outside the tape (run.py 950-972). A skipped stage becomes a zero SVF, and exp(0) and compose-with-0 are exact, so skip semantics are unchanged. The trainable level is still integrated on its own grid and composed by the trainer. The tests check native outputs bitwise against the old formulas and check that native graphs have no While op.

The chain rule is a pure, TF-free resolver. A fresh L2 run takes the flag or `native`. A fresh L1 run inherits `upstream_cascade.frozen_integration_grid`, and an explicit mismatch is a SystemExit. A resume keeps the saved value, and a mismatch is a RuntimeError. `current` without `--cascade-from` is a parse error. main.py writes the resolved value to config.json `args` and `cascade`, prints it, and passes it to every frozen factory. eval_run and the loader read it back.

Inference `fine` has its own runner methods; the native `_deform`, `_deform_sel` and sinks are untouched. Each run level's input is pre-warped with the earlier run levels' SVFs integrated at that level's grid. `u_ckpt` is the trainer's composition at the checkpoint grid, and `U1` integrates all run levels at 1 mm. This covers the default plan, truncation and skips, TTA (through the existing `_deform_stage*`) and affine+deform. The streamed path stores only centred SVFs (`FG_v<lv>`) between levels and frees them at the end. The tests show streamed == unchunked and both == the training formulas at about 1e-5.

The cost of `fine` is mostly duplicated work. At the last level the prior is integrated twice per chunk (once in the pre-warp, once in `prev_fn`). Below level 1 it is integrated a third time in the sink. Under TTA flip8, `input_fn` runs once per flip, so the pre-warp integration runs 8x. All of these calls use the non-lean sampler.

`slurm/fgi_memory.sh` follows the policy: qtim, rtx8000, 1 GPU, 3 CPUs, 128G, 3 h, and a "DO NOT submit without Jay's approval" note. It derives each config from the level script's dry-run MAIN line in a clean environment, so the recipe cannot drift. An L1 line whose L2 source failed is recorded as rc -2.

<summary>Issues (4)</summary>

1. **Repeated fine-grid integrations in the streamed runner** (confirmed, NIT): the prior SVFs are integrated in `_fine_prewarp_fn`, again in `prev_fn`, and, for a checkpoint above level 1, again in `_fine_level_sink`. With TTA flip8, the pre-warp integration repeats per flip. Cache the per-chunk prior (U, U_inv) in the store or return it from one function, and reuse it across flips.
2. **Fine integration ignores the lean sampler** (confirmed, NIT): `exp_compose_upsampled` is always called with `lean=False`, from `FrozenStage` / `FrozenChain` and from the runner (`_fine_integrate_fn`, `_fine_prewarp_fn`'s integration), even though the runner holds `self.lean` and level-1 training uses `--lean-sampler`. This raises the per-image 1 mm transient that fgi_memory.sh will measure. Consider passing `lean` through if the L1 current config is tight.
3. **check-streaming does not record the grid** (confirmed, NIT): `predict.json` gets `knobs.integration_grid`, but the check-streaming JSON only stores `checkpoint.prefix/step`. Add `rec["integration_grid"] = loaded.knobs["integration_grid"]` so an f32 gate record says which path it validated.
4. **Host-store estimate leaves out the FG_v SVF stores** (likely, NIT): `estimate_store_gb` does not count the stored level-4 / level-2 SVFs of the fine path (about 1.2 GB at an L1 checkpoint with N 101). The RAM-vs-disk choice can be slightly optimistic. Add the term, or note it.

### Training-side 'current' path and its consumers

The trainer reaches the frozen stages only through `cascade.deform`, `deform_skip` and `deform_stages` (train step 950-972, validation 1425, `_prewarp` 1796), so a FrozenStage/Chain with `integration_grid='current'` changes every consumer consistently. `FrozenChain.svfs` is valid in both modes; in native mode it uses the native `up(u4)` pre-warp, which keeps the unchunked inference path for native-trained checkpoints correct under an explicit `fine`. `deform_stages` gets `U4/U4_inv` from the same `map_fn` call (`return_first`), so the L1 frozen4 validation baseline costs no second integration. `FrozenChain.__init__` rejects a chain-level value that disagrees with its stage4, and every factory validates the value.

The level-1 memory strategy works as planned. Everything runs outside the tape, one image at a time inside `tf.map_fn(parallel_iterations=1)`. The held outputs have the same sizes as the native ones. The remaining risk is the TensorArray stacking copy and fragmentation before the forward pass. That is exactly what `fgi_memory.sh` measures. The non-lean sampler (issue 2) makes this transient larger than it needs to be.

### Inference fine path

```
streamed, L1 checkpoint, default plan:
  l4: pool(x)              -> store FG_v4 (centred v)
  l2: warp(pool(x), I2(v4)) -> store FG_v2
  l1: warp(x, I1(v4,v2)), prev_fn = I1(v4,v2) again, sink U1 = d["u"]
  (I_k = integrate_frozen_at at level k)
```

The skip and truncation cases match the trainer. Only-skipped levels so far give `warp(pool(x), 0)` and a (0, 0) prior. A level skipped after a run level is just left out, which equals a zero SVF exactly. Unchunked chain plans that skip level 2 still run model2 inside `svfs` and then drop its output. The coder documented this. It only wastes compute.

The duplicated integrations (issue 1) are a run-time cost, not a correctness problem. At L1 with chunk 2 and N 101, they add about two extra 1 mm two-field integrations per chunk. Under flip8 they add 7 more pre-warp integrations per chunk per level.

### Defaults and compatibility

Non-cascade runs keep `args.frozen_integration_grid = None`. Cascade runs record the resolved value. Resuming a pre-feature run resolves to `native` and adds the key to the resumed cascade record. No resume check compares saved args. `r_cascade.sh` only gains the key in `LEVEL_ENV_KEYS`. `r_level2.sh` and `r_level1.sh` add `GRID_ARGS` only when `FROZEN_INTEGRATION_GRID` is set, and `need_choice` is defined before it is used. The code is Python 3.8 / TF 2.10 safe: `tf.map_fn(fn_output_signature=...)`, `int.bit_length` and no new syntax. The report records the py3.8 AST check.

### Test coverage

`tests/test_fine_grid_integration.py` covers the definition of done: native bitwise and no While op, current == manual references at L2 and in the L1 chain (deform, deform_stages and all skip combinations), no input gradient, the chain-rule resolver and parse check, main.py recording plus resume rules on tiny runs, and a Trainer deform step with frozen weights unchanged. On the inference side it covers fine streamed == unchunked (default, `--levels 4`, `--levels 2`, affine+deform, L4 checkpoint, L1 chain on CPU), TTA IDENTITY_ONLY == no TTA, the loader rule with its warning, and the CLI. The full suite reported `suite status: 0` with goldens at 0 diff. Not tested: `check-streaming` end to end in fine mode (only `run` with its internal check), the L1-current fresh main.py run (6 GB local cap; covered by the resolver tests), and real-size memory (left to `fgi_memory.sh`).

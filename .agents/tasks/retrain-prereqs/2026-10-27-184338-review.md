# Retrain-from-scratch prerequisites: AdamW, tent low-res, per-stage cascade skip, delayed task start, pair cap, retrain scripts and sweep tooling

The change adds what the level 4 -> 2 -> 1 retrain needs. On the model side: an AdamW decision record with a resume guard, a shift-free `tent` low-res op on the TF augmentation path, Jay's per-task and per-stage cascade skip (`--cascade-skip-linear/-deform`), a delayed task start with an LR ramp (`--task-start-step/--task-start-ramp-steps`) and an opt-in training pair cap (`--max-pairs`). On the tooling side: three SLURM scripts (`r_level{4,2,1}.sh`), a capped memory re-measurement job, a login-node sweep helper and a run summarizer. Every new flag defaults to the old ops. The goldens stay at max |diff| 0 (`full_suite.log`: `[golden] max |diff| 0`, `[golden deform] max |diff| 0`), `tests/fixtures/` is untouched, `TestSkip` is unmodified and passes, and the full suite ran 647 tests with 0 failures and 4 skips, after the last source edit.

Watch for: the summarizer ranks runs that did not finish, and it feeds them into the phase-C length decision. A 16000-step run cut off by its time limit counts as a full 16000-step point, so the decision can come out wrong without any warning (MEDIUM).

**Verdict**: NEEDS_CHANGES

## High-level view

Defaults are bit-identical, and the code shows how. Every new path sits behind a trace-time Python switch: `max_pairs > 0`, `method == "tent"`, `_skip_mode == "stage"`, and `task_start_steps` with a start > 0. With the defaults no op is built and no result key is added. `TaskSchedule` falls back to the old cumulative table whenever every task is active. A replica of the old draw loop reproduces 10000 draws exactly, for both starts=None and all-zero starts.

The skip semantics match Jay's decision. `FrozenChain.linear_skip` / `deform_skip` make the skipped level 4 an identity and still run level 2 on the identity-pre-warped input. Skipping level 2 falls back to level 4 alone. Skipping both gives the identity. The draws are stateless, with one seed string per (task, level, seed, step). The step input is `bool[n_stages]` and each task traces once. The validation functions take no skip input. The tests check all of this, including skip4=None equality with the legacy chain path (max |diff| 0) and level-2 stage mode against legacy (max |diff| 0).

The AdamW, tent and pair-cap changes are small and well tested. One docstring misdescribes where the AMP non-finite guard lives (NIT). The tent operator is the dense static `P = U @ D` per axis. Its rows and columns sum to 1. A numpy loop reference matches it, and the centroid gate runs on the specified grid (worst 0.0167 voxel).

The scripts and helpers keep to the cluster rules. Account qtim is hard-coded, `--max-active` is capped at 2 and counts all of the user's squeue lines, `submit` refuses a dirty tree, and failed runs (including "died before start") are never resubmitted. Every dry-run main.py line goes through `runtime.args.parse_args` in the tests. Both helpers parse as Python 3.6.

The gaps are in the decision tooling and the hand-off. The summarizer does not check completion (MEDIUM). The capped memory job measures the linear tasks with a different `--min-pairs` than the knob set the scripts' TODO comments point to. The level-4 smoke never finishes the deform LR ramp. Sweep job indices depend on the phase-A grid options.

### Summarizer ranking and length decision accept incomplete runs

Section 7.3 says the summarizer "ranks the finished runs" and that a missing point makes the length decision UNDECIDED, "never a guess". `exclusion()` only checks for a missing L/Dp, non-finite finals, the non-finite fraction, collapse and folding. It never compares the step of the last validation with `args.steps`. The sweep helper itself treats such a run as `failed` (`run_progress` requires `last_done_key == steps`), so the two tools disagree on the same run directory.

Two outcomes follow. First, a phase-A or phase-B run that died mid-schedule is ranked on its last two validations. Those come from the high-lr part of the cosine, so it usually loses, but nothing rules out a run that diverged late being ranked on its pre-divergence values. Second, a phase-C 16000-step run stopped by its `--time` limit is common: the headers anticipate it ("if it exceeds the limit, resubmit with the same RUN_NAME"). It enters `length_decision` as `(16000, L_partial, Dp_partial)`. A mid-cosine L_16000 is worse than the final value, so shorter runs look "within tolerance" and the decision can return 8000 or 12000 with no warning.

```python
# scripts/summarize_runs.py, length_curve
row = summarize_run(run_dir, name, last_k, revs)
if row["excluded"] is not None:          # incomplete runs are not excluded
    ...
decision = length_decision([(r["steps"], r["L"], r["Dp"]) for r in rows])   # steps from config.json
```

The table's `step` column (`last/steps`) shows the gap to a careful reader, but the ranking and the `LENGTH` line don't.

### AMP non-finite guard in the AdamW docstring

The new module docstring says a non-finite step is skipped by "the Trainer's own `tf.cond(finite, apply, skip)`" and calls the LSO a second guard. Under AMP, which every retrain script hard-codes, the Trainer deliberately passes non-finite gradients to the LSO (comment at runtime/run.py:1004). So the LSO is the only gradient guard there. The behaviour is right; the documentation has the order reversed.

### Hand-off details: capped memory job, smoke line, sweep indices

The r_level4 / r_level2 TODO comments tell the orchestrator to take N from the "L4 linear" / "L2 linear" record "whose knob set equals the script defaults (`--min-pairs n --max-pairs 64`)". `m10_batch_memory_capped.sh` runs the linear steps without `--min-pairs`, and the tool default is 1. At N >= 32 the cap makes k = 64 for both floors, so the memory numbers transfer. Still, the record's `min_pairs` field won't literally match, and a strict reading of the fill-in rule finds no record.

The level-4 smoke moves DEFORM_START to 100 but keeps the 500-step ramp. Every deform step in the smoke therefore runs at <= 40 % lr, and the post-ramp branch of the fit loop (`s >= start + W`) never runs on the cluster before the sweep. That branch is covered locally by `TestDelayedTaskStart.test_lr_ramp`.

The sweep's global job index for phases B and C is computed from the grid of the current invocation (`n_a = len(lrs) * len(wds)`). With the documented flow (the same options every time) the indices are A 0-8, B 9-10 and C 11-12. A phase-B call with a narrower `--lrs` would reuse r4sw2..., and `state_of` identifies running jobs by name only.

## What was verified

- Level-4 bit-identity (FR13). Every cascade path is gated at trace time on `self.cascade is not None`. Skip ops are built only when `cascade_skip_prob > 0`. Non-cascade step signatures and the `train_step` call are unchanged. `_deform_errors(chunk=None)` resolves to 16. Timing and skip keys are logged only with a cascade. `warm_start_model` adds keys only when the source level differs, so level-4 records keep their nine keys. The parser allows `--cascade-from` only with `--level 2`. Goldens recorded `[golden] max |diff| 0` and `[golden deform] max |diff| 0`, in the full suite and in the integration pass.
- Composition, centering and stop_gradient. The frozen stage runs before the tape, with `training=False`, under a float32 policy, behind `stop_gradient`, and stays out of the optimizer. It sees the same post-processed, finite-zeroed tensor as the loss. The linear result is `Center(R_raw @ A_prev)` with one `GroupCentering`. The deform result is `compose_cascade(U, U_inv, u, u_inv)` inside the tape. Losses use the original images and one-hot. Validation recomputes the frozen stage inside the traced function and never skips. Frozen baselines come from the eval pass and are cached per (set, n_groups).
- BN recalibration. K > 0 without `--cascade-from` is a `parser.error` with the exact message, and a non-cascade trainer raises RuntimeError. main.py recalibrates only when `cascade_on and not cascade_resume and K > 0`. The plan uses largest-remainder allocation, interleaved; the NIT 2 index b = global plan slot. Each layer gets momentum c/(c+1), and each layer's own momentum is restored in `finally`. Non-finite slots are skipped without replacement. The pre and post passes use `validate()`, so they cannot touch the best files. Freeze is followed by `rebuild_steps()`. On resume the freeze comes only from the saved `bn_recalibration.freeze`.
- Resume and provenance (NIT 4). `cascade_resume` is decided once, before any model is built. A resume never reads the source. It raises RuntimeError when `restore_last()` returns False, checks the fingerprint (n_vars exact, sums rel 1e-12), and carries the three blocks over verbatim. Fresh runs follow the write order: config.json, params, init_weights event, recalibration, second config.json.
- Checker `grad_balance` (C4). It takes the ratio of the medians of finite `_eff` values over records with window-end `step >= 50`. KEEP iff both ratios are in [0.1, 10]; otherwise FALLBACK. UNDECIDED when values are missing or the deform median is zero. The verdict is INFO only.
- SLURM. Both scripts have `-A qtim`, no `entre`, `--gpus=1`, `-N 1`, `--ntasks-per-node=1`, `--cpus-per-task=3`, `--mem=64G`, `--time`, logs under `.../GroupwiseReg/logs`, results under `.../GroupwiseReg/results`, the sif path, `TMPDIR="$SCRATCH_ROOT/$JOB_ID"` (default `/scratch`) and `</dev/null` on every singularity call. Neither passes `--val-group-size`. The `CASCADE_FROM` guard runs only on fresh runs.
- Python 3.8 and tests. Rerun here in `bgr_preproc38`: `py_compile OK`, `ast 3.8 OK 19`, `bash -n` OK on both m8 scripts, and `tests.test_check_mixed_run tests.test_slurm_scripts` → `Ran 30 tests`, `OK`. Recorded but not rerun: full suite `Ran 381 tests`, `OK (skipped=4)`; integration pass 109 OK; preprocessing suite 142 passed.
